# Нічний розклад

[English](scheduling.md)

Claude сам не запускається. Систему роблять автоматичною чотири заплановані запуски:

| Коли (ваш часовий пояс) | Промпт | Що робить |
|---|---|---|
| щодня **01:05** | `Run the life-os email-intake workflow.` | читає нову пошту, розкладає по категоріях, створює задачі на те, що треба зробити |
| щодня **02:05** | `Run the life-os drive-file-intake workflow.` | індексує нові документи, розкладає їх по папках, записує строки |
| щодня **03:05** | `Run the life-os nightly-check workflow.` | оновлює похідні строки, перевіряє систему, надсилає один щоденний бриф |
| 1-го числа щомісяця **04:05** | `Run the life-os life-review workflow.` | місячний огляд грошей, договорів, податків і якості системи |

Промпти лишаються англійською: так скіл однозначно впізнає workflow. Відповіді, задачі й
бриф будуть мовою, яку ви вибрали.

Ще дві речі працюють без Claude і тут не налаштовуються: Apps Script bridge кожні 15
хвилин і власна задача бази `nightly-derivations` (`pg_cron`, 01:15 UTC).

## Чому вночі і чому в такому порядку

**Вночі**, бо тоді нічого іншого не відбувається: ви не читаєте пошту, не пересуваєте
документи, запуски не конкурують з вашою власною роботою в Claude, а бриф готовий, коли
ви прокидаєтесь.

**Спочатку пошта.** Bridge копіює вкладення лише тих листів, які email-intake уже поклав у
важливу категорію (рахунки, договори, органи влади, банк). Він працює кожні 15 хвилин,
тож до 01:20 сьогоднішні вкладення вже лежать у папці «Вхідні» на Drive.

**Файли на годину пізніше.** Тоді drive-file-intake знаходить ці вкладення й індексує їх
тієї ж ночі. Якщо запускати файли першими (о 01:00, а пошту о 02:00), кожне вкладення
чекатиме на індексацію цілу добу.

**Перевірка останньою.** Вона будує бриф з усього, що зробили два попередні запуски, тож
лист, отриманий сьогодні, з місячним строком оскарження потрапить у завтрашній ранковий
бриф, а не в післязавтрашній.

**П'ять хвилин після години.** Заплановані запуски рівно о повній годині можуть
стартувати на кілька хвилин пізніше, бо тоді стартують усі. П'ять хвилин після цього
уникають; година між запусками дає запас на повільну ніч.

**Огляд 1-го числа.** Він підсумовує завершений місяць. Підходить будь-який час після
нічної перевірки; 04:05 тримає його окремо від решти.

## Варіант A: routines у Claude Code (рекомендовано)

Routines працюють у хмарі Anthropic, тож комп'ютер може бути вимкнений. Доступні на
тарифах Pro, Max, Team і Enterprise.

Routine на початку кожного запуску клонує GitHub-репозиторій і завантажує скіли, які в
ньому закомічені. Цей репозиторій містить скіл у `.claude/skills/life-os`, тому routine
потрібна його копія у вашому GitHub:

1. На GitHub відкрийте репозиторій claude-life-os і натисніть **Fork** (або **Use this
   template** → **Create a new repository**). Можна приватний. Персональних даних там
   немає: усе особисте лежить у вашому проєкті Supabase.
2. Переконайтеся, що конектори Google, Gmail і Supabase (і Todoist чи Craft, якщо ви ними
   користуєтесь) підключені на claude.ai/customize/connectors. Routines використовують ті
   самі конектори, що й ваші чати.

### У браузері

Відкрийте **claude.ai/code/routines** → **New routine** і заповніть форму чотири рази:

| Поле | Значення |
|---|---|
| Name | `Life OS: email` (далі `Life OS: files`, `Life OS: nightly check`, `Life OS: monthly review`) |
| Instructions (промпт) | промпт з таблиці вище |
| Repository | ваша копія claude-life-os |
| Environment | **Default** |
| Trigger | **Schedule** → **Daily**, час з таблиці (вводиться у вашому місцевому часі) |
| Connectors | лишіть Gmail, Google Drive, Supabase, Google Calendar і Todoist / Craft, якщо користуєтесь; решту приберіть |

Натисніть **Create**. Для місячного огляду виберіть будь-який пресет, збережіть, а тоді
в командному рядку Claude Code задайте точний розклад через `/schedule update` і
cron-вираз `5 4 1 * *` (04:05 першого числа кожного місяця).

Щоб перевірити одразу, відкрийте routine і натисніть **Run now**, а потім відкрийте
запуск і прочитайте, що зробив Claude. Зелений статус означає лише, що сесія відбулася;
чи вдалася робота, видно з транскрипту.

### З командного рядка Claude Code

У будь-якій сесії Claude Code, залогіненій вашим акаунтом claude.ai:

```
/schedule every day at 01:05 in the <ваш репозиторій> repository: Run the life-os email-intake workflow.
/schedule every day at 02:05 in the <ваш репозиторій> repository: Run the life-os drive-file-intake workflow.
/schedule every day at 03:05 in the <ваш репозиторій> repository: Run the life-os nightly-check workflow.
/schedule on the 1st of every month at 04:05 in the <ваш репозиторій> repository: Run the life-os life-review workflow.
```

Claude уточнить деталі (конектори, середовище) і збереже кожну routine у ваш акаунт; вони
з'являться й на claude.ai/code/routines. `/schedule list` показує всі.

### Обмеження, які варто знати

- Routines витрачають ліміти вашого тарифу, і є денна кількість запусків routines на
  акаунт. Life OS це три запуски на день плюс один на місяць; залишок видно на
  claude.ai/code/routines.
- Routine може робити все, що дозволяють її конектори, не питаючи. Тому в списку
  конекторів має бути лише те, що потрібно Life OS.
- Якщо підключення GitHub протермінується, routines пропускають запуски, доки ви не
  перепідключите (до 72 годин), а потім вимикаються.

## Варіант B: заплановані задачі в застосунку Claude на комп'ютері

Застосунок Claude на комп'ютері може запускати ті самі промпти як локальні заплановані
задачі. Для них комп'ютер має бути ввімкнений і не спати в цей час, тож для нічних
запусків це підходить лише комп'ютеру, який не вимикається. Створіть чотири задачі з
часом і промптами з таблиці.

## Якщо ніч пропущено

Кожен запуск починає з того місця, де зупинився попередній, тож наступний усе наздожене.
База тримає watchdog (`v_intake_watchdog`): якщо email-intake чи нічна перевірка не
запускались 36 годин, а drive-file-intake 30, Apps Script bridge надішле вам лист,
незалежно від Claude. «life os doctor» показує те саме таблицею.
